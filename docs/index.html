El concepto

Qué es y por qué existe

El problema, el enfoque y el alcance real del proyecto.

PermaDrop, el proyecto de permaweb-app, es una aplicación Next.js con PostgreSQL que publica archivos de forma permanente en Arweave y los comparte con una etiqueta corta, una ficha pública y un QR. Separa contenido inmutable (los bytes y su txid) de metadatos mutables (slug, propietario, estado, contadores) y cobra en créditos internos con cotización firmada y vencimiento de 5 minutos. Incluye registro, sesiones revocables, historial, visor por MIME y panel de administración.

El repositorio empezó como scaffold vacío y se documentó como diseño; después recibió la implementación, cuyo estado verificado está en ESTADO-PROYECTO.md. No hay pasarela de compra de créditos, moderación ni antimalware, y la etiqueta es pública: no funciona como permiso de acceso. Suspender una cuenta impide nuevas operaciones, pero no retira publicaciones ya confirmadas en Arweave.

Cómo leer esta ficha

Los tropiezos salen de la bitácora y de las versiones tempranas. La evaluación usa seis criterios fijos, de 1 a 5, y no premia la espectacularidad: premia que el proyecto se pueda reproducir y entender.

01 — La idea

Un enlace que no caduca.

La permaweb promete almacenamiento permanente. La aplicación convierte esa promesa en un flujo de producto: cotizar, subir, compartir y administrar.

El problema

Los enlaces convencionales mueren cuando el proveedor cierra, cambia de precio o borra el archivo. Para documentos, portfolios y evidencia, esa fragilidad es inaceptable.

La solución

Una app Next.js que cotiza el costo de almacenamiento permanente, sube el archivo a la permaweb, guarda metadatos en PostgreSQL y expone una URL estable con QR y descarga por slug.

Tropiezos

Los tropiezos, documentados

Lo que no funcionó en las primeras versiones, con la corrección aplicada.

etapa scaffold

Un scaffold vacío documentado como proyecto

La carpeta tenía 0 archivos de código, 85 paquetes en node_modules todos vacíos y ningún package.json ni tsconfig. Se decidió documentar el estado en la primera línea del README en lugar de crear un esqueleto que diera falsa impresión de avance.

etapa documentación

Incidente de sincronización con MEGA

El cliente de sincronización renombró el README a README(1).md y luego a README(1)(1).md tras escrituras rápidas sobre el mismo archivo. Se pasó a trabajar en /tmp y copiar una sola vez, y se añadió README(*).md al .gitignore.

PermaDrop · cierre

El README de diseño quedó desfasado respecto al código

El texto se escribió sobre un scaffold y durante su redacción apareció una implementación de 79 archivos que resolvía por su cuenta proveedor, ORM y sesiones. Se agregó ESTADO-PROYECTO.md y la regla de que, donde el código y el diseño difieran, prevalece el código.

PermaDrop · verificación

Las pruebas finales no ejercitaron una subida nueva

Para evitar costes reales de Arweave, la verificación usó archivos históricos confirmados para ficha, contenido y QR. El camino completo de publicación nueva queda declarado como no verificado end-to-end en la copia.

Preguntas

Lo que suelen preguntar

¿Qué es PermaDrop?

Una aplicación Next.js y PostgreSQL que sube archivos a Arweave, guarda los metadatos en base de datos y entrega una etiqueta corta, una ficha pública, descarga y QR.

¿Borra los archivos si se suspende la cuenta?

No. El contenido confirmado en Arweave es permanente; la suspensión impide nuevas operaciones, pero la etiqueta sigue resolviendo contenido público.

¿Cómo se ejecuta?

Con PostgreSQL inicializado por npm run db:init, variables de entorno y ./start.sh en el puerto 3000; la publicación real requiere una credencial con saldo en Arweave.

¿Qué se puede reutilizar?

La separación entre contenido inmutable y metadatos mutables, la cotización firmada con caducidad y la idempotencia de ajustes y devoluciones en el ledger.
